# Repository updater

Data shapes:

- `../UPSTREAM.json`: accepted vendored-source commit and tree, schema 1. The commit belongs to `agent-skills`, not the external source repository.
- `plan.json`: immutable source/basis bindings, exact Markdown destinations, mode, and the pre-model publication probe.
- `candidate.json`: replacement text with before/after hashes, independent review, gateway receipts, and bounded Vibe run metrics. No Git patch or executable archive.
- `verified.json`: the same data after protected checks. Only this artifact may reach the publisher.
- `review-rejection.json`: fixture-failure diagnostic with a closed rejection code and bounded reviewer fields. Untrusted data, never a candidate or publication input.

The checkpoint on the default branch advances only when a human merges the update PR. A failed run discards its checkout and leaves the accepted checkpoint unchanged.

## Execution

`.github/workflows/update-pstack-hermes.yml` uses fresh GitHub-hosted Ubuntu runners. It runs after successful completion of the existing upstream-sync workflow. It also reconciles daily at 14:35 UTC and supports manual dispatch. It does not rely on a push generated by the default Actions token triggering another push workflow.

| Job | Authority and work |
| --- | --- |
| `plan` | Read-only checkout. Compare immutable old/new source trees. Map destinations and stop unsupported changes. Deduplicate a pending proposal by source and adaptation trees. |
| `adapt` | Build pinned Vibe. Run offline policy checks, one restricted writer, and a fresh restricted reviewer. Only the internal gateway holds the real provider credential. |
| `verify` | Fresh runner. Reconstruct validated text operations. Run protected contracts, updater tests, retained Bun tests/typechecking, and the native Hermes loader. No model or publisher credential. |
| `publish` | Fresh runner with repository/PR write permission. Recheck main, source, original probe, scope, and bot branch. Append a normal commit and read back the exact PR head. No model credential. |

The writer compares old upstream, new upstream, and the current Hermes adaptation. It does not replace the adaptation with a new upstream copy. Existing agent documents map to the two shipped bot SOUL skeletons, not live profiles.

Writer and reviewer both use `mistral-large-4` through Mistral's API. They have separate contexts. This is not independent model-family evidence. Human review remains required, especially for semantic changes and safety instructions.

## Boundaries

- Only known existing Markdown counterparts and the package index may change automatically.
- New/deleted/renamed files or skill directories, executable/non-Markdown changes, links, modes, invalid text, and unmapped scope stop before adaptation.
- Frontmatter stays byte-identical. Automatic output cannot introduce or alter inline shell templates.
- Tests, automation, workflows, historical verification evidence, the checkpoint, and unrelated content are not model-writable publication targets.
- The writer gets no repository token, real provider key, Git checkout, live home, messaging configuration, or Docker socket.
- Docker enforces read-only input/policy mounts, a bounded writable candidate, non-root execution, dropped capabilities, resource limits, and internal-only networking. Profiles and worktrees are not used as security sandboxes.
- The gateway exposes only the pinned model route. It injects authentication itself, denies redirects, and writes receipts outside the AI's mounts.
- Raw Vibe transcripts, session journals, and provider errors are not publication artifacts. Host logs expose only a bounded tool-effect projection: fixed kind/status/target/error labels and boolean success, never tool arguments, paths, output, messages, or reasoning. Gateway receipts are run evidence, not provider-signed attestations.
- Published data comes from the verifier's exact artifact ID in the current workflow, not a branch-supplied filename or a model's claim that tests passed.

The existing upstream sync remains a separate privileged workflow. This updater neither runs that sync itself nor edits its vendored output on repository branches. Fixture mode changes source only in disposable runner checkouts and cannot publish.

## Runtime pins and budgets

`runtime.json`, `vibe-config.toml`, and `Dockerfile.worker` hold the reviewed pins. Vibe is `2.26.1`; its Linux wheel hash is checked before installation. Hermes verification uses an immutable Git revision. Bun is `1.4.3`. Action implementations are pinned to commit SHAs.

The Python base tag and dependency hash closure are not a complete reproducible-image lock. Review upgrades as policy changes. Do not change a version and assume its permissions, export schema, or fallback behavior stayed compatible.

Each role has one attempt: 40 Vibe turns, 150,000 tokens, an estimated $2 limit, and a 900-second Vibe deadline. These are client limits, not a provider-enforced billing ceiling. The gateway separately bounds requests, request bytes, generation, response bytes, and elapsed time. There is no unbounded repair loop.

Gateway defaults per role: 40 attempts, 262,144 bytes per request, 1,500,000 cumulative request bytes, one completion, at most 8,192 generated tokens per request, and a 1,200-second deadline. A provider-side project budget is needed for a hard account billing limit.

Successful pending proposals are deduplicated. Failed adaptations remain outstanding and retry on later reconciliation. Disable the workflow if repeated failures should stop spending before a fix.

Vibe uses its explicitly selected Unified harness. Its native capability catalog is not the four legacy file-tool schemas; native grep is not advertised in this release. The offline gate compiles the real route and verifies shell/process denial. Unknown aliases, fallback warnings, missing credentials, unavailable models, failed/limited exports, and zero usage block publication. The pinned Unified adapter maps Vibe `thinking="low"` to explicit Mistral `reasoning_effort="none"`; `off` would omit that field. Raw/effective config must preserve `low`, an offline SDK request assertion proves the mapping, and the gateway independently forces outgoing `reasoning_effort="none"`. Unified can forward the whole-session token setting as a completion cap, so the gateway also independently clamps each completion to 8192.

## Repository configuration

Required configuration:

- Actions secret `MISTRAL_API_KEY`. Rotate it through the credential store or GitHub Secrets. Never paste it into a workflow, prompt, command argument, report, or committed file.
- Actions variable `PSTACK_VIBE_MODEL=mistral-large-4`. Any other value blocks the worker rather than selecting another model.
- Actions may create PRs. GitHub combines PR creation and approval in one repository setting; the updater never approves or merges PRs. Default workflow permissions remain read-only. Only the publisher job requests write permission.

No Hermes profile model, credential file, bot routine, or installed skill tree is changed by this repository automation.

## Run and inspect

After the workflow is merged into the default branch:

```bash
gh workflow run update-pstack-hermes.yml --repo ThomsenDrake/agent-skills -f mode=reconcile
gh workflow run update-pstack-hermes.yml --repo ThomsenDrake/agent-skills -f mode=fixture
```

To verify the initial unmerged implementation without running the vendor sync:

```bash
gh workflow run update-pstack.yml --repo ThomsenDrake/agent-skills --ref pstack-hermes-updater -f verify_updater=true
```

That existing registered workflow calls the new reusable workflow at the selected revision. The `sync` job is skipped. The controlled source rule contains `PSTACK_UPDATER_SMOKE`; verification requires the real Vibe-produced adapted file to preserve it. Fixture publication is blocked in both workflow and controller.

Inspect the run's exact commit, conclusion, job logs, and normalized artifacts. On a rejected fixture audit, download the `pstack-review-rejection-<run>-<attempt>` artifact and read it as untrusted data. It expires after three days. The run stays failed; reconciliation does not emit this diagnostic, and neither verifier nor publisher consumes it. Raw CLI logs, sessions, config, and provider errors are excluded. A queued run, configured model, or successful authentication is not an end-to-end pass. Native Hermes verification lists and loads all shipping skills/support files without inference or template rendering. It is loader evidence, not proof of every skill's live behavior. The fresh AI review and human merge review address semantics.

## Recovery and policy changes

A stale main/source/basis or an unexpected bot-branch head stops publication. Retry reconciliation against the new basis. The publisher never force-pushes, deletes a branch, or overwrites manual bot-branch edits.

A human-closed unmerged bot PR blocks further publication. Reopen the intended PR or resolve the state through a human-reviewed policy change. Do not silently recreate a rejected proposal.

One branch, `automation/pstack-hermes-update`, holds append-only proposals. A merged old PR does not block the next source change. If a run stops after pushing but before PR creation, a retry checks the exact verified tree before recovering the missing PR. If a push succeeds but updating an existing PR fails, rerun the failed publisher job with its original verified artifact and protected pre-model probe. Exact-tree recovery repairs only that PR metadata, without another commit or push. A fresh reconciliation deliberately rejects the ambiguous stale-body state; it is not a substitute for the original artifact. Main must remain unchanged for this recovery.

Review the source/base hashes again before merging a proposal if main moved after its verification. A prior verdict is not a claim about all future base revisions. Merging the PR does not update any installed Hermes profile; reinstall that profile deliberately and verify it separately.

To expand eligible changes, update the protected protocol, expected inventory, executable integrity checks, native loader gates, and relevant fixtures in a separate human-reviewed PR. The model cannot edit these gates to make its output pass.
