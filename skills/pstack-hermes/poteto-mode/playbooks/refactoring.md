### Refactoring

**You own the contract. The structure changes. The behavior does not.** Feature adds behavior. Bug fix corrects it.

If cleanup reveals a missing feature or real bug, split it out and keep this structural change against the pinned contract. Name a redesign and route it to `skill_view(name='poteto-mode', file_path='playbooks/feature.md')`. Large cross-cutting work loads `skill_view(name='figure-it-out')`. This playbook covers focused-to-medium changes.

1. Pin behavior first. Load `skill_view(name='how')` to learn the subsystem contract. Write and run a characterization test, snapshot, or equivalence harness before moving structure. If coverage is missing, write the pin first. Typecheck and lint are not a behavior pin.
2. Load `skill_view(name='principle-model-the-domain')` and name the missing structure. Keep boring code when the shape is already clear and local. The reshape must remove branches or invalid states, not add indirection.
3. State the target module layout, types, and call graph as if built today. Load `skill_view(name='principle-foundational-thinking')` and `skill_view(name='principle-redesign-from-first-principles')`. If it crosses a function boundary, load `skill_view(name='architect')` for shape exploration before the move.
4. Subtract first. Load `skill_view(name='principle-subtract-before-you-add')` and delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before adding the shape. Load `skill_view(name='principle-laziness-protocol')` and keep only the smallest change that reaches it. Revert speculative cleanup, not unrelated edits.
5. Move in small behavior-preserving steps and keep the pin green. Load `skill_view(name='principle-migrate-callers-then-delete-legacy-apis')` for API reshapes. Migrate all callers and remove the old API in the same wave, without permanent shims or parallel paths. Search strings, prose, and back-references with `search_files`, not just typed usages. Use `delegate_task(tasks=[{'goal': '<mechanical reshape>', 'context': '<exclusive worktree/files, old and new names, pinned behavior, tests, forbidden actions, report>'}])` when available. The child inherits the parent model and is not a recursive coordinator. Otherwise make the bounded edits directly with `patch` and review separately.
6. Load `skill_view(name='principle-prove-it-works')`. Prove unchanged behavior on the real artifact. For larger reshapes, diff old/new outputs, replay a recorded baseline, or smoke the same surface using the repo's driver through `terminal` or available Hermes browser/computer-use tools. Optional control integrations are not assumed installed. Verify child receipts yourself.
7. Load `skill_view(name='principle-minimize-reader-load')` and decide whether the result earns its place. Name the removed layer, mutable state, branch, or hidden dependency. If reader load did not fall anywhere, revert the reshape.
8. When commits are authorized, keep subtraction, reshape, and follow-on cleanup in small ordered slices. Load `skill_view(name='principle-sequence-verifiable-units')` and check each slice before the next. For an authorized PR, load `skill_view(name='poteto-mode', file_path='playbooks/opening-a-pr.md')`.

**Reply:** changed structure, behavior pin, equivalence proof, reader-load delta, what was kept and reverted, and verification output. No new behavior.
