### Autopilot-stack

**One-shot launch gate.** Before any profile-process launch here, load `skill_view(name='pstack-hermes', file_path='references/one-shot-safety.md')`. `-z` bypasses command and hook approval gates. Require explicit authorization for that bypass, review inherited hooks, and verify restricted execution boundaries, scoped credentials, and minimal toolsets. Model-diversity or unattended-work requests are not bypass authorization. Otherwise use bounded parent-driven delegates, an approval-preserving interactive session, or report blocked.

**You own the stack, never the landing. Hand the operator one linear chain of base-targeted PRs to review and land.** Load `skill_view(name='poteto-mode', file_path='playbooks/autopilot-full.md')` first. Its build, verification, ownership, and actual Hermes lifetime rules apply except where this playbook differs. Reload both installed playbooks at each audit and record their approved revision; do not assume a copied skill is tracked on project trunk.

1. **Use Autopilot-full's owner phases without landing.** Owners report `STACK-READY`, not merge-ready permission to land. They never rebase onto another branch, retarget, merge, close a PR, or arm auto-merge. The root owns topology and the operator owns landing. A dependent owner branches from its parent's exact tip, not trunk. Native `delegate_task` carries only a bounded owner phase, inherits the parent model, and is not a durable coordinator. The root schedules follow-up phases and independent verifiers; no recursive fan-out is assumed.
2. **Give topology one writer.** Owners push only their own branches within the publishing grant and report current tip and intended parent. Only the root performs authorized rebases or retargets, after quiescing that branch's owner and recording the remote lease. Append each clean PR in dependency order with its base set to its parent's branch. For GitHub, use `terminal(command='gh pr edit <pr> --base "<parent-branch>"', workdir='<repo>')`, then read back that exact PR's base/head. Optional Origin uses its inspected equivalent; no Graphite dependency. An owner accepts the root's recorded push as its new base/lease. It resolves conflicts only in its exclusive slice and hands the result back for the root's serialized topology update.
3. **Absorb drift at the root before landing.** Apply Autopilot-full step 5's tested-merge-result rule to each link and rebase bottom-up where required. Load `skill_view(name='poteto-mode', file_path='playbooks/shipping.md')` and apply the patch-id/context rule link by link, because a link's base is its parent. Every changed head gets current checks, and changed behavior gets fresh verification. Same-model lanes are the default, not multi-model evidence.
4. **Deliver the chain, then keep hands off.** Each PR carries or links the verified verdict for its exact head. Posting that verdict needs comment authority; otherwise deliver the artifact in the operator report. No automation merges under this playbook. Once the operator starts landing, nobody writes the chain except the post-merge next-child retarget explicitly assigned by the operator and sanctioned in Shipping. A mid-landing problem goes through the root to the operator. A fix waits for the operator's go. A stop cancels new dispatches and known owned terminal jobs; unconfirmed child cancellation must be disclosed and its scope quarantined.

**Choose between the autopilots.** Use Autopilot-full for independent PRs only when explicit landing authority exists. Use Autopilot-stack when the operator wants review before landing, work is coupled/sequenced, or merge authority is withheld. Durable unattended work requires actual approved background `hermes -p <profile> -z` terminal runs or a configured scheduler, not a claim that delegation survives its parent. Finish independent work and end the turn for native background completion delivery; do not poll child transcripts.
