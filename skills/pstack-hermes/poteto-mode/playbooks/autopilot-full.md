### Autopilot-full

**One-shot launch gate.** Before any profile-process launch here, load `skill_view(name='pstack-hermes', file_path='references/one-shot-safety.md')`. `-z` bypasses command and hook approval gates. Require explicit authorization for that bypass, review inherited hooks, and verify restricted execution boundaries, scoped credentials, and minimal toolsets. Model-diversity or unattended-work requests are not bypass authorization. Otherwise use bounded parent-driven delegates, an approval-preserving interactive session, or report blocked.

**You own the verdicts, not the implementation. One owner role carries each independent PR through its phases. Nothing merges until independent verification covers the code that lands.** A role is durable in the program record; a native child process is not.

A verdict covers a patch and its relevant context. Green CI covers a head. Run a full verification matrix once at code-ready, and again for a major behavioral change. Load `skill_view(name='poteto-mode', file_path='playbooks/shipping.md')` for the patch-id/context rule. Every new head still needs current checks.

1. **Honor the operator's gates first.** Record the exact queue, allowed paths/actions, resource budget, named review gates, and landing authority. Items reserved for the operator and PRs outside the queue stop at merge-ready. A request to state the plan is not a go. Full autonomy never expands authority to messages, approvals, secrets, unrelated work, deployments, or protected-branch bypasses.
2. **Assign one owner per PR and externalize its state.** Resolve the forge once, authenticated `gh` by default. Optional Origin requires installed-help and repo-resolution checks. Never require Graphite or a cloud-agent service. Give every owner an exclusive worktree/branch, exact allowed files, success criteria, check commands, a durable brief/report path, and explicit forbidden actions. Load `skill_view(name='show-me-your-work')` and record owner identity, current phase, last observed/pushed SHA, runtime budget, evidence, and next action in an approved durable store.

   The native path is bounded phase dispatch through `delegate_task(tasks=[{'goal': '<build, fix, or verify one phase>', 'context': '<full brief, workspace, grant, latest head, gates, report path>'}])`. Children inherit the parent model and have isolated contexts. Do not give a child a model/speed flag or require it to spawn a verifier. After it returns, the coordinator audits the artifact and dispatches a fresh consolidated brief for the next phase. Parent-owned terminal watchers cover waits. Results arrive between parent turns; do independent work, then end the turn instead of polling transcripts. If delegation is unavailable, implement phases directly and obtain independent verification separately; self-review cannot satisfy an independent verifier gate.

   When the user explicitly requests a run that outlives this conversation, use an operator-configured named profile with the required tools and shared worktree/store access. Launch a real job with `terminal(command='hermes -p <profile> -z "<full scoped owner brief and checkpoint contract>"', workdir='<exclusive worktree>', background=true, notify=true, persist_on_release=true)`. Record its terminal session ID, run/report path, and observed model identity. Keep parent/worker credentials and permissions scoped. Persistence covers session cleanup, not host restart, and is not provided by delegation. Do not create or change profiles as an implicit prerequisite.

   Before creating a PR or any PR-facing push, complete the mandatory parent-owned delegated-PR gate in `skill_view(name='poteto-mode', file_path='playbooks/opening-a-pr.md')`. Every delegated PR requires interrogate, cleanup, and no-comments, not only contested designs. The bounded owner implements, removes boilerplate/speculation, runs local checks, and returns its stable head/diff and cleanup/check receipts without publication. The coordinator then dispatches independent reviews itself, handles accepted fixes in later bounded phases, and accepts the exact snapshot before authorized ready publication. A code leaf never spawns the reviewers. Missing independent review blocks publication. Before code-ready, run path-relevant checks on the committed head, rebase onto current trunk only with topology authority, and report the exact head before proof. Later fix rounds keep that base unless trunk conflicts or breaks checks. Report every new head and remote readback. Push retained units only when publishing is authorized. Force-push only an exclusively owned branch within the grant, with a lease pinned to the last observed remote SHA. On an unexpected push, stop ownership transfer rather than overwriting it.
3. **Run independent owners off trunk, not stacked.** Parallel work uses separate worktrees and disjoint ownership. Dependent changes route to `skill_view(name='poteto-mode', file_path='playbooks/autopilot-stack.md')`. Never infer safe sharing from isolated conversations.
4. **Run the verification matrix at code-ready.** Load `skill_view(name='swarm')` and dispatch bounded independent verifier lanes from the coordinator, not recursively from leaf owners. Default to same-model lanes and label them honestly. True model-family diversity requires operator-configured named profiles and separate `terminal` runs; it is not evidence supplied by parallelism alone.

   Include gates, load-bearing live behavior on the actual surface, perf where the plan requires it, and independent audits of the diff and receipts. Drive the repo's CLI/UI harness through `terminal` or available Hermes browser/computer-use tools after discovering dependencies. No mandatory control plugin. The verdict is not clean without the live lane or your audit of merge-ready receipts. A child summary is not proof. Each lane names exact base/head, commands, output, artifacts, and pass/fail. A blocked lane is not a pass.

   Batch every proven finding into one fix-forward to the owner, including a defect filed as a note. Require a red-first proof across all sites with that defect. A preexisting trunk issue does not gate unless this PR copies or newly reaches it. Never push a competing fix to the owner's branch. Keep one writer. A full matrix reruns for new behavior, redesign, or a large diff; minor fixes/rebases get a fresh targeted verifier at the new head plus current CI, subject to the shipping equivalence rule.
5. **Merge only what was verified on the trunk it will land on.** Green CI is not landing authority. Only after an explicit grant, operator gates, accepted root verdict, and merge-ready evidence may the owner or designated lander enter the merge phase. Merge prep rebases onto current trunk when required, reports the new head, and waits for current checks. Use the exact bottom-up and readback safeguards in `skill_view(name='poteto-mode', file_path='playbooks/shipping.md')`. Require an accepted current verdict for the exact full `<verified-head-sha>` and equality with the PR's fresh `headRefOid`. The GitHub merge command is `terminal(command='gh pr merge <pr> --squash --match-head-commit <verified-head-sha>', workdir='<repo>')`. On mismatch, stop and reverify, never repin to an unverified head. Read the exact PR afterward and verify merged state, trunk base, and accepted head; never use an admin/protection bypass. Do not arm auto-merge or enqueue landing here. Inspect branch rules before invoking the command and stop at merge-ready if it would defer automatically. A request-time pin or promised freeze is not enforced immutable head semantics. Queue-only landing is blocked pending a separately approved service with immutable head semantics and continuously current verdicts.

   Immediately before merge, fetch trunk and determine whether drift can affect the patch. Rebase and rerun checks if a conflict, changed shared file, or changed check selection means the landing result was not tested. For lockfile-only overlap, a frozen install on the actual merge result plus equivalent resolutions for changed packages can establish safety; failure requires repair. If trunk changed callers, dependencies, or called code, run the patch's checks on the merge result. Unrelated drift alone need not cause endless rebases. After repeated colliding rebases, hold that PR and sequence the work at the root. Never claim a queue/auto-merge request actually merged without exact forge readback.
6. **Run the root audit.** A gate relaxation, raised budget, or allowlist change requires verifier evidence and explicit approval within the operator's grant. Never disable/soft-fail a check or supply a forge-enforced approval. A root countersign cannot bypass the operator or branch protection. Record the approved head and proof.

   Record an audit cadence before fan-out, normally hourly for long programs. Use an available documented Hermes session loop only within its process lifetime, or an explicitly authorized terminal/scheduler mechanism. There is no assumed editor loop or nested durable fleet. At each actual wake, reload `skill_view(name='poteto-mode', file_path='playbooks/autopilot-full.md')` and approved plan/standing orders. Check owner phase, known terminal process status, pushed heads, receipts, and gates against the record. Never poll a native child's transcript while awaiting its delivered result. A timeout or missing output needs diagnosis, not an automatic second writer. Before replacement, stop/revoke the old writer or quarantine its worktree and branch and use a new isolated scope. A waiter on an operator decision is not stuck. Report only newly tracked changes and log every audit row.
7. **Stand down on the operator's stop.** Stop dispatching and merging at once. Stop owned terminal watchers/runs through available process controls, preserve their checkpoints, and verify that no authorized auto-merge remains armed when cancellation is supported. Do not pretend you can message an already-returned child. If a running child cannot be cancelled, state the limitation, quarantine its scope, and do not dispatch a replacement into it. Resume only with the updated grant and a fresh consolidated brief.
