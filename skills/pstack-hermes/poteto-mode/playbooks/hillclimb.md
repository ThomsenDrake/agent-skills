### Hillclimb

**You own the metric and the experiment's integrity. Supervise and review. Delegate bounded attempts when available.** This is sustained improvement of one measurable thing against a target. A one-off fix belongs to Bug fix or Perf issue.

One change, one measurement, keep or revert. Never stack untested changes or claim a win from inspection. Load `skill_view(name='principle-prove-it-works')`.

1. Ground the workload and architecture with `skill_view(name='how')`. Name realistic dimensions such as data size, history, state, and concurrency, then select a case that reproduces the complaint. If it does not reproduce, fix the repro before hillclimbing. Fix one metric, the better direction, and a checkable stop predicate with both a target and an attempt floor, such as "at least 50% better and at least 10 iterations". Use the user's numbers or agree on them before spending a long run. Set a resource budget and correctness gates. Never broaden authorization to reach the target.
2. Load `skill_view(name='principle-build-the-lever')`. Build the harness, prove sensitivity with contrasting realistic workloads, and then freeze it. The target case must reproduce the symptom while easier cases separate as expected. If the harness cannot distinguish them, revise it before freezing. Load `skill_view(name='benchmark-checklist')` to vet units, warmup, samples, environment, errors, and work count. One repeatable `terminal` command emits a noise-resistant metric, such as median of N, plus error and work counts. Record the baseline and a green regression-gate run before changing code.
3. Load `skill_view(name='show-me-your-work')`. Open a gitignored `decision.tsv` under the approved artifact store, not a shared source file. One row per attempt includes id, hypothesis, change, before, after, computed delta, tests, kept/reverted verdict, and note. Read it before each attempt.
4. Ground each hypothesis in the architecture model. Name the mechanism, not "try memoizing something". For performance, borrow the mantra order from `skill_view(name='poteto-mode', file_path='playbooks/perf-issue.md')`, not that playbook's early-stop rule.
5. Loop one hypothesis per iteration.
   - Use `delegate_task(tasks=[{'goal': '<one hypothesis>', 'context': '<exclusive worktree, allowed files, frozen harness, regression gate, forbidden actions, report>'}])` when available. Children inherit the parent model, have isolated contexts, and do not recursively fan out by default. Without delegation, make the bounded change and keep a separate review. Load `skill_view(name='principle-guard-the-context-window')` and review the actual diff, not the summary.
   - Several independent hypotheses may run in separate worktrees. Load `skill_view(name='principle-separate-before-serializing-shared-state')`. Do not compare simultaneous noisy measurements on a contended host. Re-measure a selected change after integration, without combining untested attempts.
   - Measure before and after with the frozen harness and run the regression gate through `terminal`. Compute deltas with a tool and inspect errors/work counts. Accept only a move beyond noise with the gate green. Otherwise revert only that attempt in full. A tweak that "might help" is not kept.
   - When commits are authorized, make one commit per accepted fix and stage exact owned paths, never unrelated changes. Log the row either way. Preserve actual output as receipts.
   - Load `skill_view(name='principle-sequence-verifiable-units')`. Each iteration ends in a check before the next. For unattended waits, borrow only the wake mechanism from `skill_view(name='poteto-mode', file_path='playbooks/autonomous-run.md')`, not its stop rule. After background delegation, do independent work and end the turn for result delivery rather than polling transcripts.
6. Push past the first plateau. After several rejects, pivot category, combine near-miss hypotheses as a new measured attempt, re-read source, or try a different mechanism. Correctness and simplicity outrank the number. Load `skill_view(name='principle-laziness-protocol')`. Revert a performance win that breaks behavior, and a simplification that holds the number may be kept without calling it a speedup.
7. Stop when the predicate is met, or report a budget limit, real blocker, or exhausted ideas with evidence. Do not relax the predicate or quit while cheap hypotheses remain within budget. A resource stop is not target success. Surface a dead end instead of spinning indefinitely.
8. For an authorized PR, load `skill_view(name='poteto-mode', file_path='playbooks/opening-a-pr.md')` with accepted commits in verified order.

**Reply:** metric and target, baseline to final with a tool-computed percent delta, attempt counts kept/reverted, each accepted fix, exact harness command, decision-log path, remaining predicate state, and the best next idea.
