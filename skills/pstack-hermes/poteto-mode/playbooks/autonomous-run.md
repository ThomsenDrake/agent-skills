### Autonomous run

**One-shot launch gate.** Before any profile-process launch here, load `skill_view(name='pstack-hermes', file_path='references/one-shot-safety.md')`. `-z` bypasses command and hook approval gates. Require explicit authorization for that bypass, review inherited hooks, and verify restricted execution boundaries, scoped credentials, and minimal toolsets. Model-diversity or unattended-work requests are not bypass authorization. Otherwise use bounded parent-driven delegates, an approval-preserving interactive session, or report blocked.

**You own the exit condition. Define done, then drive to it within the actual grant and resource budget.** Autonomy changes pacing, not authorization.

1. State a checkable exit predicate before the first iteration, such as green named tests, a fixed repro, an explicitly authorized merged queue, or zero pixel diff. Record allowed paths and actions, operator gates, time/cost budget, and safe stop conditions. "Keep going" does not authorize merges, messages, secrets access, deletion, deployment, or changes outside the grant.
2. Pick a real wake mechanism. For synchronous local work, iterate directly with `terminal`, `read_file`, `search_files`, and `patch`. For an external event such as CI or a ref advance, start one parent-owned watcher with `terminal(command='<bounded watch command>', background=true, notify=true)`. Inspect its help and give it a deadline. Use `process_manage` for that terminal job, not for child transcript polling. Do not add a second sleep loop beside a watcher. A documented Hermes session loop or cron is optional only if available and authorized; it must have an explicit interval, budget, predicate, and stop path. No editor-specific loop or durable watcher child is assumed.
3. Each iteration makes the smallest evidence-justified change, verifies the predicate, and keeps only what advanced the task. Commit only when authorized. Discard speculative changes without discarding another owner's work. Load `skill_view(name='principle-sequence-verifiable-units')` and check each unit before the next.
4. Handle discoveries that block the predicate within the granted scope. A broken skill, tool failure, flaky verifier, or related bug is not automatic permission to edit another profile, publish a new PR, send a message, or access credentials. Isolate an authorized side fix and return to the predicate. Record out-of-scope follow-ups and ask only for a genuine scope or product decision, missing access, irreversible action, or dead end.
5. Checkpoint every iteration with `skill_view(name='show-me-your-work')`. Record what changed, the evidence, whether the predicate moved, retained/discarded attempts, and the next action in an approved durable store. Scratch probes go under `$TMPDIR`, not an assumed system path.
6. For a bounded subtask, use `delegate_task(tasks=[{'goal': '<bounded result>', 'context': '<workspace, allowed paths/actions, predicate, tests, report>'}])` when available. Children inherit the parent model, have isolated contexts, and are not durable coordinators. Do independent work, then end the turn for completion delivery between turns. Do not poll transcripts or claim the child survives a parent exit. For explicitly requested work that must outlive the conversation, use an operator-configured profile through `terminal(command='hermes -p <profile> -z "<full bounded brief and checkpoint path>"', workdir='<approved workspace>', background=true, notify=true, persist_on_release=true)`. Record the terminal session ID and verify process/result state. This survives session cleanup only, not a host restart; durable schedules need an authorized scheduler.
7. Stop on predicate success, operator stop, exhausted budget, unsafe boundary, or a genuine dead end. A plateau alone calls for a new approach, not a weakened predicate. Report a non-success stop plainly and leave a checkpoint via `skill_view(name='poteto-mode', file_path='playbooks/pause-safely.md')`.

**Reply:** exit predicate, iterations, verified work, discarded attempts, final predicate state, evidence/store paths, and any specific gate that prevented completion.
